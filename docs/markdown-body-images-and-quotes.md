# TASK-109・TASK-103 本文画像と文書の引用コメント

## 本文画像

- 通常のMarkdown画像記法 `![代替テキスト](/api/body-images/<uuid>)` を保存する。アップロード完了前の参照は保存時と固定版生成時に拒否する。
- 要件定義書の目的・章本文、個別要件の内容・受け入れ条件・背景、一般文書、タスク説明、画面・API設計の概要、テスト設計の説明で同じ挿入処理を使う。DB設計をMarkdownの一般文書として管理する場合も同じ操作を使える。構造化された項目・表のセルは各機能の入力仕様に従う。
- 画像はPNG・JPEG・WebP、3 MiB、2,000万画素まで。展開と形式を検証する。下書きは利用者・案件ごとに24件、本文は32種類、案件総数は512件まで。保存時に同じ案件と画像用途を確認し、送信者本人の下書きだけを確定する。
- 固定版は公開時に確定済みの画像を参照する。ゲスト向けの画像取得では、現在の資料閲覧許可・固定版の部分・本文に含まれる参照を照合する。すべての配信に `private, no-store` を適用する。
- 未確定の画像は取り消せる。24時間を経過した下書きは同じ利用者の次回アップロード予約時に少数ずつ回収する。確定済み画像は履歴や固定版から参照可能なため、本文で削除した後も保管する。

| 操作 | API |
| --- | --- |
| 画像の予約・送信・確定 | `POST /projects/{project_id}/body-images/{kind}/{upload-plan,upload,upload-complete}` |
| 下書きの取消 | `DELETE /projects/{project_id}/body-images/{kind}/{image_id}` |
| 社内向け配信 | `GET /body-images/{image_id}` |
| ゲスト向け配信 | `GET /shared/publications/{publication_id}/nodes/{node_id}/body-images/{image_id}` |

画像のメタデータは既存の `comment_images` に保存し、用途と `retained_at` で扱いを決める。Alembic `b2a8ed7f3c16` を適用する。本文画像が保存された環境では、旧コードへ戻す場合も拡張済みスキーマを保持する。

## 文書の引用コメント

「本文」タブは章・目的・未分類要件ブロックの表示テキストに対する半開区間を記録する。HTMLテキストノードのDOM位置からUnicode code pointへ変換し、連続空白・ブロック境界は半角スペースにまとめる。画像の代替テキスト・画像UI・図のSVG・チェックボックスは位置計算から外す。日本語・絵文字・結合文字を原文の並びで保持する。画像に触れる範囲選択は登録対象外。

アンカーは既存の `target_anchor` に `rendered-text-v1` として保存する。文書ID・対象ブロック・文書版・章版、最大千文字の引用、範囲と前後48文字、比較用の表示テキストを持つ。本文変更後は引用件数の減少がなく、前後文脈または変更前後で連続して同一の領域に十分な文脈があり、候補が両方の版で一意の場合に再特定する。見つからないときも元の引用とコメントは読める。旧アンカーは保存された表示相当テキストが一致し、引用が一意の場合に移動可能。

`PATCH /projects/{project_id}/comments/{comment_id}/anchor` は投稿者または既存のコメントモデレーターが使用する。コメントの `version` と、現在の文書・章版を照合する。引用とコメント版だけを更新し、操作前後・操作者・時刻を要件定義の変更履歴に記録する。

固定版レビューでは、固定済みノードの原文から選択範囲に対応するUnicode code point位置を取得する。原文に連続した範囲として対応する文字列を引用できる。編集版の再指定は固定版レビューコメントに適用されない。

設計資料は [CommonMark の画像記法](https://spec.commonmark.org/0.31.2/#images) と [W3C Web Annotation のセレクター](https://www.w3.org/TR/annotation-model/#selectors)。
