# プロジェクト概要 API

`GET /projects/{project_id}/overview` は `project:read` 権限で利用する。要件、タスク、テスト、Issue はそれぞれ `requirement:read`、`task:read`、`test_case:read`、`task:read` に応じて集計し、権限のない領域は `null` を返す。対応行と履歴も同じ権限で除外する。

- `requirements`: 有効な要件数と、現在有効なテスト項目の関連を持つ／持たない要件数。「カバー」は検証の十分性ではなく関連の有無。
- `tasks`: 不具合種別を除く有効タスクの件数、完了、期限超過、ブロック。
- `tests`: 有効な設計から生成済みの現在有効なケースだけの最新状態。過去の実行履歴、削除／無効化された組み合わせのケースは加算しない。実施済みは OK と NG の和。
- `issues`: 不具合種別の有効タスク件数と未解決件数。NG ケースとは別に数える。
- `attention`: 期限超過、ブロック、Issue未登録NG、NG、未解決Issue、テスト未カバー要件の順に最大10件。期限超過かつブロックのタスク、Issue未登録かつNGのケースは重複しない。
- `activities`: 直近8件。要件変更履歴、タスク変更履歴、テスト設計監査ログ、テスト実行履歴を日時順に統合する。

`GET /projects/{project_id}/activities?page=1&page_size=20` は同じ権限規則で履歴全体をページングする。`has_more` で次ページの有無を判断する。履歴は既存データの読み取り専用投影であり、新たな履歴テーブルやマイグレーションは必要ない。
