## 最新の決定: 通常利用とデモ利用を共存させる

ユーザーの確認・修正指示を受け、専用資源の準備を「既存API全体をデモDBへ切り替える」計画に
拡張した誤りを訂正する。以下を現在の設計・受け入れ条件とする。
下記の作業履歴にある接続先の切り替え・通常回収との排他・全体のメール無効化は、当時の記録であり、
現在の運用指示として使用しない。公開環境の通常接続先は維持し、デモ接続だけを追加している。

| 合意 | 現在の設計・受け入れ条件 |
| --- | --- |
| 通常アカウントを維持 | 通常ログイン・通常セッションは既存DB、既存Storage、既存JWT鍵を使用する |
| デモだけ専用資源 | デモ開始・検証済みデモセッション・デモ回収は専用DBと専用Storageを使用する。通常接続へのfallbackはしない |
| 実行環境と機能を分離 | `APP_ENV=production`を維持し、`DEMO_MODE`はデモの受付・利用可否だけを制御する |
| 既存構成・無料運用 | 現在のFastAPI・Frontend・認証/RBAC・S3互換を維持。APIを増設せず、Backend内で検証済みセッションに応じて接続を選ぶ |
| 通常メール・30日保持 | デモ有効時も通常ユーザーのメール処理と通常ごみ箱回収を維持する。デモデータへ通常回収を実行しない |
| デモ利用範囲 | 通常業務と組織内管理まで。運営管理はBackendの認可で拒否する |
| デモデータの破棄 | ログアウト・リセット・失効でアクセスを即時停止し、専用資源から回収する。遅延PUTと障害時の再試行は台帳で継続する |
| ブラウザの下書き | 通常ユーザーの永続下書きを維持し、デモはセッション内のみ。別DBで数値IDが重なっても混同しない |
| AI支援・Eve | 取りやめ。既存stashは保持。将来のCodex向けMCPで要件定義・テスト設計の作成を検討する |
| 公開反映 | 2026-10-08のユーザー指示でマージ・適用・公開環境変更を承認。通常接続の置き換え・追加費用・想定外の変更が必要なら操作前に相談する |

齟齬の原因は、資源作成の承認と通常データを含む実行先変更の承認を区別せず、
通常ログインを維持する条件を設計・回帰テストへ入れなかったこと。
修正では署名検証前のCookie内容・ID・クライアント指定を接続選択に使わず、
通常とデモの独立した署名鍵で検証したセッションだけを振り分ける。
同じ数値ユーザーID・リソースIDを持つ2つのDBで、通常利用の維持とデモの回収を検証する。

## 決定事項

- `APP_ENV` は `development` / `test` / `production` の実行環境を表す。
- 公開する通常環境・デモ環境はともに `APP_ENV=production` とする。
- デモ機能は独立した `DEMO_MODE=true` で有効にする。未設定時は false。
- Frontend / Backend / Terraform / デプロイ時のCron生成を同じ方針に揃える。
- デモでもHost検証、BFF認証、Secure Cookie、CSRF、レート制限、DBのTLS検証を維持する。
- デモ専用DB・非公開ストレージの分離確認、デモセッションのメール抑止、JWT/BFFと別のCron秘密は引き続き必須。
- 通常業務と組織内管理をデモに開放する。運営管理は開放しない。
- ログアウト・リセット・セッション失効ではアクセスを直ちに失効し、DB・ファイルとブラウザの一時下書きを破棄する。回収の再試行を維持する。
- デモ回収と通常の30日保持・ごみ箱回収は接続先を分け、デモ有効時も通常回収を維持する。

## 修正理由

2026-10-07の相談では `APP_ENV=production` + `DEMO_MODE=true` を提案し、その後の実装が承認された。
実装では確認を挟まず `APP_ENV=demo` に寄せたため、提案・実装・公開手順に不一致が生じた。
環境のセキュリティ設定とデモの機能設定を分離し、当初の方針に戻す。
今後この決定を変更する場合は、実装前に理由と影響をこの記録へ追記し、ユーザーと確認する。
