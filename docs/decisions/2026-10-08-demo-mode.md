# デモ機能と実行環境を分離する

決定日: 2026-10-08。状態: ローカル実装・検証・コミット完了、push・公開反映は未実施。

## 決定事項

- `APP_ENV` は `development` / `test` / `production` の実行環境を表す。
- 公開する通常環境・デモ環境はともに `APP_ENV=production` とする。
- デモ機能は独立した `DEMO_MODE=true` で有効にする。未設定時は false。
- Frontend / Backend / Terraform / デプロイ時のCron生成を同じ方針に揃える。
- デモでもHost検証、BFF認証、Secure Cookie、CSRF、レート制限、DBのTLS検証を維持する。
- デモ専用DB・非公開ストレージの分離確認、メール無効化、専用Cron秘密は引き続き必須。
- 通常業務と組織内管理をデモに開放する。運営管理は開放しない。
- ログアウト・リセット・セッション失効ではアクセスを直ちに失効し、DB・ファイルとブラウザの一時下書きを破棄する。回収の再試行を維持する。
- デモの回収と通常データの30日保持・ごみ箱回収を混在させない。

## 修正理由

2026-10-07の相談では `APP_ENV=production` + `DEMO_MODE=true` を提案し、その後の実装が承認された。
実装では確認を挟まず `APP_ENV=demo` に寄せたため、提案・実装・公開手順に不一致が生じた。
環境のセキュリティ設定とデモの機能設定を分離し、当初の方針に戻す。
今後この決定を変更する場合は、実装前に理由と影響をこの記録へ追記し、ユーザーと確認する。

## 変更範囲と移行

1. Backend: 設定、デモAPI・サービス、メール抑止、通常回収の排他、Cron生成、環境変数例。
2. Frontend: Server Componentで `DEMO_MODE` を読み、デモ開始操作の表示に使う。
3. Infra: `demo_mode` をboolで追加し、両プロジェクトへ `DEMO_MODE` を設定する。`app_env=demo` を廃止する。
4. テスト・運用手順: productionとデモの組み合わせ、無効時の拒否、保護と破棄の維持を検証する。

APIのURL・入出力、DBスキーマ、RBAC、セッション所有関係は変更しない。Alembic migrationとOrval再生成は不要。
旧 `APP_ENV=demo` は設定エラーとして拒否し、暗黙の互換変換は行わない。
既存の公開環境は前回の公開確認時点で `APP_ENV=production`、デモ無効であり、未設定の `DEMO_MODE` は false として扱う。
デモの有効化は、専用DB・ストレージを用意した後、BackendとFrontendの両方に `DEMO_MODE=true` を設定して再デプロイする。
この修正作業では公開設定変更・Terraform apply・デモ有効化は行わない。
