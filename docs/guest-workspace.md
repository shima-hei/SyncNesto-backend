# TASK-113 ゲストの参加と固定版の共有

Project #5 の TASK-113（作業126）は TASK-042（作業55）の UAT-15／UAT-16 を扱う。指摘と再受入条件は文書20 第12版、認識合わせと固定版の正式承認は文書8 第8版を参照する。

## 現行機能との対応

| 領域 | 継続して使うもの | この変更 |
| --- | --- | --- |
| 本人と参加 | `users.user_type`、既存ログイン・MFA、メールでの招待確認、`project_guest_participations` の参加世代 | 通常所属のないゲストの入口を `/shared` にする。案件別の公開概要と参加期限変更を追加 |
| 文書・版・添付 | `artifact_releases`、封印された公開用表現、採用済み保全添付、本人別公開許可 | 個別要件の共有を要件単独の固定版で開始。設計・テスト設計の詳細から共有準備を開く。新しい画面は添付取得時にサーバーで認可を再評価 |
| 判断 | 要件ワークフロー、既存の正式承認、公開許可と本人の固定承認バインディング | 参加案件ごとに本人の依頼を絞り込む。個別要件単独の固定版を既存の認識合わせに接続 |
| コメント | 社内コメント、既存の認識合わせスレッド、共通の会話表示・メンション入力・リンク挿入部品 | 固定版に専用のスレッドと返信を追加。共有時の候補検索と固定版リンクの解決に、現在の公開許可を使う |
| 通知・監査 | 招待メール、既存の承認通知・受信設定、操作台帳・監査ログ | 資料共有とゲスト本人への返信・メンションをアプリ内で通知。期限変更・公開概要・認証付きファイル配信を記録 |
| BFF・MCP | CSRF・Origin、HttpOnly セッション、現在のプロジェクト権限 | BFF の本人限定経路を `no-store` にし、組織選択ヘッダーを転送しない。共有用の操作を MCP ツールに登録しない |

## 認可

| 操作 | 未参加・失効 | 参加のみ | 固定版の閲覧許可 | 投稿許可あり | 本人宛ての有効な判断依頼 |
| --- | --- | --- | --- | --- | --- |
| 公開用案件概要 | 拒否 | 可 | 可 | 可 | 可 |
| 固定本文・採用画像の閲覧 | 拒否 | 拒否 | 可 | 可 | 閲覧許可も必要 |
| 共有スレッド閲覧 | 拒否 | 拒否 | 可 | 可 | 閲覧許可も必要 |
| 共有スレッドへの投稿・返信 | 拒否 | 拒否 | 拒否 | 可 | 投稿許可も必要 |
| 共有スレッドのメンション候補検索 | 拒否 | 拒否 | 拒否 | 可 | 投稿許可も必要 |
| 添付のダウンロード操作 | 拒否 | 拒否 | 個別許可が必要 | 個別許可が必要 | 個別許可も必要 |
| 認識合わせ・承認・差戻し | 拒否 | 拒否 | 拒否 | 拒否 | 可 |

新しい共有経路では、アクセス時点のセッション、本人、組織、案件、参加世代、封印された公開版、許可を照合する。参加・共有の取消は既存のロックと世代単位の更新で処理する。期限変更は有効な参加世代を確認した版で更新し、失効した世代は作り直す。新しい参加世代に過去の共有・判断依頼は引き継がない。

ゲストの未回答の要件ワークフローでは、設定済みの回答期限を日本時間の日付で判定する。設計書・テスト設計書の正式承認では、共有期限以内の回答期限を時間まで指定できる。回答期限後も、独立した資料閲覧許可が有効なら固定本文を閲覧できる。

概要に使う項目は `guest_project_profiles` に保存する。未設定時は空欄になる。既存 Project の名前・説明・日程・ユーザー属性は共有用プロフィールへ流用しない。概要と共有資料の絞り込みには参加世代の UUID を使い、組織・案件の内部 ID をゲスト向けレスポンスへ含めない。

共有コメントは固定公開版に属し、返信と本文のアンカーは同じ固定版を複合外部キーで参照する。投稿を許可された本人は、現在その版を閲覧できるゲストと、その版ですでに共有投稿をした社内担当者をメンションできる。社内担当者には現在の組織・案件所属と固定版の全構成の読取権限を要求する。候補が返すのは既に共有されている表示名と候補専用の識別子。投稿時に同じ版の許可、候補の表示名、本文内の UTF-16 の文字位置を照合する。固定版の共有相手全員に表示されることを確認して投稿する。

ゲスト画面のリンクは、リンク先も現在閲覧できる同一オリジンの共有固定版である場合に、その公開タイトルを取得して展開できる。社内資料やタスクのURLは入力された文字列として表示する。社内の閲覧画面では既存のリンク解決と資料種別ごとの認可を使う。

共有、返信、メンションの通知は既存通知テーブルに保存する。表示時は通知の付与IDと現在許可された付与IDを照合し、現在の公開版から資料名を取得する。通知には本文を複製しない。返信とメンションが同じゲスト宛ての場合はメンション通知を1件登録する。共有や参加を取り消すと通知の一覧と未読数から消え、同じ資料を再共有しても古い通知は復活しない。

社内担当者宛ての返信とメンションは通常の通知一覧に届く。同じ人への返信とメンションは1件にまとめる。現在の所属、公開状態、固定版の全構成の閲覧権限を、通知の一覧・未読件数・既読操作のすべてで照合する。通知は固定版の共有スレッドを開く。本文とゲストのユーザー識別子は通知レスポンスに含めない。[OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

新しい画面からの添付取得は BFF 経由で記録し、オブジェクトストレージの URL を返さない。取得前後に共有許可の世代と採用済み添付の同一性を確認する。画像のインライン表示は許可したラスター形式に限定する。旧クライアントとの互換用署名 URL は `download_allowed IS NULL` の旧契約の許可に限定され、発行済み URL はその署名期限まで使える場合がある。表示や保存済みのデータは利用者の手元に残り得る。

参照した一次資料は [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)、[OWASP API1](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)、[OWASP API3](https://api-security.owasp.org/editions/2023/en/0xa3-broken-object-property-level-authorization/)、[Amazon S3 presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)、[PostgreSQL locks](https://www.postgresql.org/docs/current/explicit-locking.html)、[Next.js data security](https://nextjs.org/docs/app/guides/data-security)。

## 画面と操作

1. 社内の案件メンバー画面の「ゲスト管理」から、公開用概要を保存し、ゲストを招待する。受諾後は参加状態、期限、参加世代の共有資料と判断依頼を確認できる。判断依頼の一覧には、対象の固定版、本人の回答、期限、共有の失効状態が表示される。対象を開くと既存の依頼詳細から操作できる。
2. ゲストは確認メールから、既存のアカウント設定・ログイン・追加認証を通って受諾する。ホームの参加案件から公開用概要に移動する。案件内は「概要」「共有資料」「確認・承認」「コメント」で切り替える。
   共有資料一覧では追加認証後に「要対応」「回答済み」「依頼なし」を表示する。本人の期限内の未回答依頼を優先する。「確認・承認」には公開用案件名と対象の固定日時を表示する。
3. 社内担当者は資料の保存済み内容から公開準備版を作る。資料の共有では相手・期限・既に採用された添付を確かめて、コメント投稿とダウンロードを必要に応じて許可する。旧版は既存の共有一覧から確認・停止できる。
4. 判断依頼は既存の本人指定の操作で作る。個別要件は認識合わせ、要件定義書全体・設計書・テスト設計書は正式承認を使用する。依頼対象・版・本人は保有する権限と照合し、結果や差戻し履歴は既存の固定版に保持する。
   依頼画面では、個別要件の認識合わせと要件定義書・設計書・テスト設計書の正式承認で、本文と添付、ゲスト本人、共有期限を確認できる。同時共有で追加する未共有の相手は、画面では1名を指定する。正式承認のプレビューは内容と共有設定を検証し、確定時に共有許可と依頼を同じトランザクションへ保存する。依頼詳細から取消を行うと、今回付与した共有許可が失効する。[PostgreSQL のトランザクション](https://www.postgresql.org/docs/17/tutorial-transactions.html)
5. 資料を開くと固定本文、採用添付、共有コメントが表示される。参加・共有を取り消すと、新しい画面取得・添付取得・判断操作が拒否される。
   投稿できる人は、固定本文で範囲を選んで共有コメントへ引用できる。キーボードでは投稿欄で対象箇所を選び、「固定本文から引用」を開く。コメントに引用文が表示され、リンクから元の項目を開ける。対象は要件定義書と章・個別要件の本文項目、設計書のタイトルと目的、テスト設計書のタイトル。
   共有コメントと返信には、画像（PNG・JPEG・WebP）、PDF、テキスト、JSON を添付できる。1ファイル3 MiB、1投稿4件まで。投稿前に名前と画像プレビューを確認できる。固定版を閲覧できる本人は画像を表示でき、ダウンロード操作には固定版の許可が必要。
   投稿欄で `@` を入力し、同じ固定版を閲覧できるゲストや、すでに共有投稿をした社内担当者を選ぶ。候補は上下キーと Enter で確定できる。共有資料のURLを貼り付けるか、リンク挿入から指定すると、閲覧可能なリンク先の公開タイトルを展開する。返信・メンションの通知から該当スレッドと返信を開ける。
6. 社内担当者は、要件定義書・個別要件・設計書・テスト設計書の資料詳細から、初期表示の「内部コメント」と「共有コメント」を切り替える。「共有コメント」でその資料を主対象に固定した公開版を選ぶ。選択肢に公開状態と公開版の保存日時、選択後に本文の固定日時が表示される。公開停止の版は閲覧でき、投稿は公開中の版で公開操作の権限を持つ担当者に限る。引用は「固定本文を開く」から選ぶ。現在の資料で箇所を指定して指摘すると、内部コメントに戻る。タブを切り替えても編集中の下書きは各投稿欄に残る。[W3C のタブ設計パターン](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

## API とデータ

| 経路 | 応答・書込条件 |
| --- | --- |
| `GET /shared/projects` と `GET /shared/projects/{participation_id}` | 本人に有効な参加世代と公開用概要 |
| `GET/PUT /projects/{project_id}/guest-profile` | 案件管理権限と版番号。更新と監査記録は同じトランザクション |
| `PUT /projects/{project_id}/guest-participations/{participation_id}/expiry` | 参加管理権限、有効世代、版、理由、再送 ID |
| `GET /projects/{project_id}/guest-participations/{participation_id}/grants` | 参加管理権限と各資料種別の読取権限を両方要求 |
| `GET /projects/{project_id}/guest-participations/{participation_id}/decisions` | 同じ参加世代・公開版・付与に結び付く判断のみを返す。管理者自身の要件・固定版・全構成の読取権限を照合した集合で、件数とページを計算する |
| `GET /shared/publications` と既存の判断依頼一覧 | 参加世代による絞り込み。共有資料一覧には公開用案件名と共有日時を追加。判断の追加認証を通った本人へ、表示中の固定版の対応状態と再確認時刻を返す。判断依頼一覧の案件名も公開用プロフィールの値を使う |
| `POST /projects/{project_id}/guest-requirement-reviews` | 個別要件の認識合わせで、`sharing` を指定すると確認済み固定版の閲覧許可を依頼と同時に作成 |
| `POST /projects/{project_id}/guest-requirement-reviews/{request_id}/cancel` | 依頼の版と取消理由を確認し、判断依頼とそれに付随する共有許可を同時に終了 |
| `POST /projects/{project_id}/guest-requirement-approvals` の `/preview` と確定、`/{request_id}/cancel` | 要件定義書の正式承認。`sharing` に共有範囲と相手、`due_on` に回答期限を指定し、確定時に確認 digest を照合 |
| `POST /projects/{project_id}/guest-fixed-approvals` の `/preview` と確定 | 主資料が設計書またはテスト設計書の固定版で、`sharing` に新しい共有先1名、`decision_expires_at` に回答期限を指定。既存の固定承認の取消経路から付随許可を停止 |
| `GET /projects/{project_id}/artifact-publications` | `source_kind` と `source_id` で固定版の主対象を指定できる。`state` は複数指定できる。同じ案件・封印済み固定版・全構成の現在の読取権限・絞り込み条件を一覧と件数に適用する |
| `GET/POST …/publications/{publication_id}/comments` と内部の公開版コメント経路 | 対象固定版の許可を確認。トップレベル投稿の `anchor` は同じ版の `node_id` と `field`、`quote`、Unicode コードポイントの `quote_start` で照合。返信は親スレッドの範囲を継承 |
| `GET …/comments/mention-candidates` | 投稿可能な本人に、同じ固定版を閲覧できる他のゲストと共有投稿済みの社内担当者の表示名・候補IDを最大30件返す。投稿時に対象固定版の現在権限を再確認する |
| `GET /shared/publications/link-titles` | 最大50個の固定版IDのうち、現在の本人に許可された固定版の公開タイトル・期限のみ返す |
| `POST …/comments/files/plan`、`POST …/comments/files`、`POST …/comments/files/complete`、`DELETE …/comments/files/{file_id}` | 投稿権限、本人、固定版、許可世代を照合して添付下書きを管理する。コメントの `attachment_ids` で投稿と同じトランザクション中に確定する |
| `GET …/comments/{comment_id}/files/{file_id}/content` | コメントに確定した添付を現在の閲覧許可で取得する。ラスター画像の表示とダウンロードを区別し、転送前後で許可と対象を確認する |
| `GET /shared/comments` | 閲覧可能な固定版と共有スレッドをページ取得 |
| `GET /shared/activity` と `POST /shared/activity/{notice_id}/read` | 資料共有・返信・メンション・要件の判断依頼の本人通知と既読。通知時の共有許可を照合し、依頼通知は本人宛て・取消・回答期限も確認。ホームは `unread_only` と `comments_only` で未読の返信・メンションだけを取得 |
| 既存の社内 `/notifications` | 共有コメントの通知については、現在読める同一固定版とメンション先または親投稿の著者を照合する。固定版とスレッドの参照を返し、成功・エラーを保存禁止にする |
| `GET /shared/publications/{publication_id}/files/{file_id}/content` | 本人許可の `revision`、採用済みの添付、操作区分を取得時に照合 |

共有コメントの親子・アンカーは物理制約で版を揃える。同じ投稿の再送は本人・版・再送 ID を結び付け、内容が異なれば競合にする。承認の二重判断・取消との競合は既存のトランザクションとロックを継続する。

### 保存先と状態

| 対象 | 保存先・状態と制約 |
| --- | --- |
| 本人と参加 | 既存の `users` と `project_guest_participations` を使用。本人と案件の参加世代を記録する。有効期限の到達は有効性の判定に使い、取消済みや期限切れの参加を再利用する場合は新しい世代を作る |
| 公開用案件概要 | `guest_project_profiles` は案件ごとに1件。公開用項目と更新版を保持し、監査へ更新を記録する |
| 資料と閲覧許可 | `artifact_releases` が固定元となり、`artifact_publications` の準備版を公開または停止する。本人の `artifact_publication_grants` は固定公開版と参加世代を参照し、操作許可・期限・付与元・停止理由を保持する |
| コメント | `shared_publication_comments` は固定公開版と親スレッドを参照する。添付は下書きから投稿確定へ進み、メンションは投稿時の有効な付与を参照する。新しい固定版への移行処理は行わない |
| 判断履歴 | 既存の `requirement_workflow_requests` と `fixed_approval_requests` が正本。ゲスト用バインディングは参加世代と公開版・付与を保持する。回答と差戻し・取消は既存の終端と履歴に記録し、再依頼は新規の依頼となる |
| 通知と管理履歴 | `notifications` には通知 ID、宛先と参照だけを保存する。ゲストの表示に使う資料名は現在の許可を確認して取得する。公開・失効の業務履歴は `artifact_publication_events` に保持する |
